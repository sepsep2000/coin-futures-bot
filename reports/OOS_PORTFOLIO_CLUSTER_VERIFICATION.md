# OOS_PORTFOLIO_CLUSTER_VERIFICATION.md — 포트폴리오 레벨 클러스터 수 실측

OOS_PORTFOLIO_APPLICATION_PROPOSAL.md의 추천안(방식 3: D5/D7b 클러스터
정의, 포트폴리오 레벨 적용)을 SPEC.md에 명문화하기 전, 실제 결합
포트폴리오의 독립 클러스터 수를 실측한다. 스크립트:
`scripts/diag/oos_portfolio_cluster_verification.py`(기존
`checks.signal_validation.cluster_events()` 그대로 재사용, 신규 클러스터링
로직 없음). 원본: `reports/diag_data/oos_portfolio_cluster_verification.csv`,
`oos_portfolio_pooled_events.csv`.

## 단순 합산 vs 풀링재군집화 — 어느 쪽이 맞는가 (D5 원본 방법론 기준)

D5/D7b의 24h 클러스터링은 **같은 신호 메커니즘 안에서** 발생하는 자기상관을
보정하기 위한 것이다 — 같은 추세 국면이 연속된 봉에 걸쳐 반복 신호를
내는 것처럼, "같은 데이터生성 과정"이 만드는 종속성을 다룬다.

filtered_trend(단일자산 추세추종)와 2a(20자산 횡단면 상대가치)는 서로
다른 메커니즘이고, 이미 여러 차례(SIGNAL_VALIDATION_2a.md, FILTERED_
TREND_2A_CORRELATION.md, ENGINE_MULTI_CORRELATION_UPDATE.md) 주간수익률
상관계수가 -0.06~-0.10 사이(임계치 0.3에 한참 못 미침, 반복 확인됨)로
독립임이 실증됐다. 두 신호의 이벤트가 우연히 같은 주에 겹친다고 해서
정보가 겹치는 게 아니다 — 오히려 두 독립 메커니즘의 이벤트를 시간
근접성만으로 풀링해 재군집화하면, 진짜 분산된 포트폴리오일수록(사건이
서로 무관하게 여기저기 흩어져 있을수록) 우연한 캘린더 겹침이 늘어나
독립 관측치 수를 부당하게 과소평가하는 방향으로 편향된다.

**판단: 단순 합산이 방법론적으로 맞다.** 다만 실측으로 두 방식의 차이를
직접 비교해 이 판단이 실제로 결과를 좌우하는지 확인했다(아래).

## 실측 결과

| 항목 | 값 |
|---|---|
| filtered_trend: 원시 트레이드 / 독립 클러스터 | 638 / 283 |
| 2a: 원시 이벤트(리밸런스 주) / 독립 클러스터 | 185 / 185 |
| **단순 합산(283+185)** | **468** |
| 풀링재군집화(두 신호 이벤트를 합쳐 24h 규칙 재적용) | 419 |
| 풀링재군집화에서 두 신호가 섞인 클러스터 수 | 46개(전체 419개 중 11%) |

풀링재군집화가 단순 합산보다 49개 적다 — 이는 위에서 예상한 대로,
서로 무관한 두 신호의 이벤트가 우연히 24h 이내로 겹친 경우들을 (정보가
겹치지 않는데도) 하나로 합쳐버린 결과다. 이 46개 혼합 클러스터는
"진짜 자기상관"이 아니라 "우연한 캘린더 근접"이므로, 단순 합산(468)이
더 정확한 독립 관측치 수라고 판단한다.

## 판정

| 방식 | 클러스터 수 | 300 기준 |
|---|---|---|
| 단순 합산(채택) | 468 | **PASS** |
| 풀링재군집화(참고, 기각) | 419 | PASS(참고로도 통과) |

**두 방식 모두 300을 넘는다** — 이번 판단(단순 합산 채택)이 통과 여부를
바꾸지 않는다는 뜻이다. 즉 이 채택은 "통과시키기 위해 유리한 쪽을
고른 것"이 아니라, 어느 쪽을 쓰든 결과가 같은 상황에서 방법론적으로
더 정확한 쪽(단순 합산)을 골랐을 뿐이다.

**최종 수치: 468개 ≥ 300 → PASS.**
